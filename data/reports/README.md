# `data/reports/`

Auto-generated reports from the current package's own hyperparameter sweep and evaluation tooling — distinct from `data/research_history/pjm_load/reports/`, which holds the historical Week 1–7/Phase 2 research reports.

| File | Written by |
|---|---|
| `results_summary.md` | `enerdatasynth report` (`evaluation/results_report.py`) |
| `hyperparameter_results.csv`, `hyperparameter_summary.md` | `enerdatasynth sweep` (`training/sweep.py`) |
| `failure_analysis.md` | `enerdatasynth evaluate` (`evaluation/failure_analysis.py`) |
| `benchmark_comparison.csv` | `examples/run_benchmark.py` |
| `future_experiments.md` | Hand-written — recommended next experiments, not yet implemented |
| `figures/` | Validation plots (`enerdatasynth evaluate`) |

These numbers describe the legacy MLP sweep — the only architecture with a bundled, compatible checkpoint today (see `data/checkpoints/README.md`) — not the Transformer. `docs/results.md` is the canonical, cross-checked results reference for the project as a whole, reconciling both the current package's own numbers and the historical research numbers with sources traced. Read that first. This folder is where the current-package numbers actually come from, and it gets overwritten the next time you re-run `sweep`/`evaluate`/`report`.

## What should not be placed here

Anything meant to be a permanent, versioned result. This folder is regenerated by re-running the commands above, not hand-curated.

Wind has its own equivalent reports at [`wind/`](wind/README.md), written by `enerdatasynth evaluate --resource wind` / `enerdatasynth report --resource wind`.
